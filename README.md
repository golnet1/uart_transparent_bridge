# Pass-Through UART — ESP-IDF мост UART + Web + Telnet + OTA

Лёгкий мост на ESP32: два последовательных порта прозрачно связаны между собой,
весь трафик дублируется в USB-UART (UART0), а управлять и смотреть поток можно
через встроенный веб-интерфейс, telnet или сам USB-терминал.

Подробное описание внутреннего устройства, всех подсистем и потоков данных —
в файле [MODULE.md](MODULE.md).

## Возможности

- **Сквозной мост:** UART1 ↔ UART2. При включённом `echo` принятые байты
  дублируются обратно в порт-источник.
- **USB-зеркало:** UART0 (встроенный USB-UART bridge) показывает HEX+ASCII весь
  проходящий через мост трафик. Системные логи ESP-IDF тоже можно вывести туда
  (по умолчанию выключено, чтобы не засорять зеркало).
- **Отправка команд:**
  - веб-форма (текст или HEX, выбор UART1 / UART2 / оба);
  - **адресная строка браузера** (`/sec?hex=41540D&target=3`) — HEX-команда,
    `/sec?log=50` — чтение ответа из журнала;
  - **MQTT** — команды в HEX через `<топик>/rx[/1|2|3]`, ответ `<топик>/result`,
    трафик `<топик>/traffic`, статус `<топик>/status`;
  - telnet (`send 1 AT`, `sendhex 2 41 54 0D`, `raw on`);
  - USB-терминал (просто текст → выбранный UART; `/help` — локальные команды).
  - В веб-карточке «Каналы команд (HEX)» выбирается режим: адресная строка,
    MQTT или оба одновременно.
- **Автокоманда от ESP32:** периодическая отправка строки на любой UART
  (`auto <мс> <1|2|both> <текст>` или в вебе).
- **Автоопределение скорости UART1/UART2:** отдельные выключатели на каждый порт;
  ESP32 перебирает стандартные скорости и шлёт понятные команды (по умолчанию
  `AT|AT+GMR`), ожидая ответ `OK` или `ERROR`. Найденная скорость показывается
  в вебе, `/api/status` и CLI (`status`).
- **Журнал:** кольцевой буфер в RAM (32 КБ), просмотр в вебе/telnet, очистка,
  выгрузка последних N строк через `/api/log`. В вебе строки журнала переводятся
  вместе с выбранным языком интерфейса (в том числе уже загруженные).
  Выпадающий фильтр в мониторе показывает все сообщения, только системные
  (`SYS/WIFI/OTA`) или только команды и трафик UART/USB.
- **Веб-интерфейс:** один встроенный HTML (без SPIFFS и внешних CDN), WebSocket
  для живого лога. Язык — выпадающий список с картинками флагов
  `RU` / `EN` в шапке; выбор сохраняется в браузере.
- **Telnet:** порт 23, до 4 клиентов, обработка IAC, `monitor on|off`; при подключении
  запрашивается пароль (ввод без echo, таймаут 60 с).
- **Доступ по паролю:** веб-панель открывается по секретному пути, например
  `http://10.10.100.235/sec` (по умолчанию пароль/путь `sec`). Корень `/` отдаёт
  `401 Password is not specified`, неверный путь — `401 Wrong password`.
  Тот же пароль используется для Telnet; меняется в вебе (карточка «Безопасность»,
  новое поле вводится дважды для контроля) или командой `passwd <новый>`.
- **OTA:** два OTA-слота в `partitions_ota.csv`. Прошивка загружается локальным
  `.bin`-файлом из браузера или с GitHub (`raw.githubusercontent.com`, HTTPS через
  встроенный набор корневых сертификатов). Версия проверяется при загрузке модуля
  и раз в сутки; при включённой галке обновление ставится автоматически.
- **Wi-Fi:** SoftAP `UART_BRIDGE` / `12345678` и STA с сохранёнными настройками.
  Если STA подключён к точке доступа, AP автоматически отключается; при потере
  STA-соединения AP включается снова. Настройки и скорости сохраняются в NVS.
- **Время:** SNTP (`pool.ntp.org` по умолчанию, настраивается), часовой пояс
  POSIX TZ (`MSK-3` по умолчанию). После синхронизации журнал и веб-монитор
  показывают реальное время; до неё — время с момента загрузки.

## Пины по умолчанию

| Канал | TX | RX | Скорость |
|-------|----|----|----------|
| UART1 | GPIO4 | GPIO5 | 115200 (меняется) |
| UART2 | GPIO25 | GPIO26 | 9600 (меняется) |
| USB (UART0) | GPIO1 | GPIO3 | 115200 (фиксированная) |

Пины задаются макросами `UART1_TX_PIN`, `UART1_RX_PIN`, `UART2_TX_PIN`,
`UART2_RX_PIN` в `main/uart_bridge.c`.

## Автоопределение скорости UART

В карточке «Сквозной мост UART» есть выключатели **UART1 автоскорость** и
**UART2 автоскорость**, а также поле **Команды определения** (по умолчанию
`AT|AT+GMR`). Можно задать свои команды через `|`, например `AT|ATI|ATE0`.
ESP32 последовательно пробует скорости 1200…921600 бод, посылает каждую команду
с `\r\n` и считает скорость найденной, если в ответе появилось `OK` или `ERROR`
(без учёта регистра). Пока идёт опрос, сквозная пересылка через этот мост
приостановлена, поэтому пробовые байты не уходят на другой UART.

Если ни одна команда не ответила, ESP32 пишет предупреждение в лог и остаётся
на скорости из поля «UART1 скорость» / «UART2 скорость». Результат виден:

- в вебе — подсказка под полем команд (`UART1: определено 9600`);
- в `/api/status` — поля `auto_baud1`, `auto_baud2`, `baud_probe`,
  `baud1_detected`, `baud2_detected`;
- в CLI — команда `status` показывает `автоскорость: UART1 найдена, ...`.

Из CLI то же самое делается командой:

```
autobaud 1 AT                  только UART1, своими командами
autobaud 2 AT|AT+GMR           только UART2
autobaud both                  оба порта, команды по умолчанию
autobaud off                   выключить автоопределение
```

## Сборка и первоначальная прошивка по USB

Нужен ESP-IDF v4.4+ (рекомендуется v5.5.x). В Windows сначала активируйте
окружение ESP-IDF (запустите `export.ps1` из папки фреймворка, например
`. C:\Espressif\frameworks\esp-idf-v5.5.2\export.ps1`), затем перейдите
в каталог проекта.

1. Подключите ESP32 к ПК через USB (на плате используется USB-UART bridge на
   UART0). В «Диспетчере устройств» найдите номер COM-порта, например `COM4`.
   Если `esptool` не подключается, удерживайте кнопку `BOOT` (GPIO0) в момент
   начала прошивки.
2. Соберите проект:

   ```powershell
   idf.py set-target esp32
   idf.py build
   ```

   `idf.py menuconfig` запускать не обязательно: таблица разделов и нужные
   опции уже прописаны в `sdkconfig.defaults`.
3. Прошейте:

   ```powershell
   idf.py -p COM4 flash
   ```

   Для чистой установки (удалить старые настройки из NVS) сначала выполните
   `idf.py -p COM4 erase_flash`. Обычная `flash` раздел NVS не трогает —
   сохранённые настройки Wi-Fi/MQTT останутся.

   Можно сразу прошить готовыми образами из репозитория, без сборки:

   ```powershell
   python -m esptool --chip esp32 -p COM4 --before default_reset --after hard_reset write_flash 0x1000 build\bootloader\bootloader.bin 0x8000 build\partition_table\partition-table.bin 0xf000 build\ota_data_initial.bin 0x20000 build\PassThroughUART.bin
   ```

4. После прошивки ESP32 перезагрузится. Подключитесь к `UART_BRIDGE` /
   `12345678` и откройте `http://192.168.4.1/sec` — дальнейшие обновления
   можно ставить уже по воздуху (см. раздел «OTA»).

`idf.py monitor` использовать не нужно: из-за `CONFIG_ESP_CONSOLE_NONE=y`
консольный вывод отключён. Логи смотрите в веб-мониторе, по Telnet или в
USB-зеркале (команда `syslog on` дублирует их в UART0).

Таблица разделов задаётся через `sdkconfig.defaults`. Если у вас уже есть sdkconfig,
убедитесь, что включено:

```
CONFIG_PARTITION_TABLE_CUSTOM=y
CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="partitions_ota.csv"
CONFIG_HTTPD_WS_SUPPORT=y
CONFIG_ESP_CONSOLE_NONE=y
```

## Подключение

1. Подключитесь к Wi-Fi `UART_BRIDGE` (пароль `12345678`) — откроется AP IP
   `192.168.4.1`.
2. Браузер: `http://192.168.4.1/sec` (или `/<ваш пароль>`; просто `/` — 401
   `Password is not specified`).
3. Telnet: `telnet 192.168.4.1 23`, пароль по умолчанию `sec`.
4. USB-терминал: 115200 8N1. Введите `AT` — уйдёт на оба UART; `/help` — список
   локальных команд.

Если задать SSID/пароль вашей сети в вебе или командой `wifi <ssid> <pass>`,
ESP32 подключится к роутеру как STA, и интерфейсы станут доступны по выданному
ему IP (например, `http://10.10.100.235/sec`). При подключении к роутеру AP
отключается, а при потере STA-соединения включается снова.

## Telnet / USB команды

```
help                          список команд
status                        состояние, счётчики, IP
target 1|2|both|usb           цель по умолчанию для этой сессии
raw on|off                    весь ввод сразу в UART
send 1 AT+CSQ                 отправить текст на UART1
sendhex 2 41 54 0D 0A         отправить байты на UART2
send both AT                  на оба UART
baud1 9600 | baud2 115200     сменить скорость
autobaud 1|2|both|off [команды]  автоопределение по ответу OK/ERROR
bridge on|off                 сквозная пересылка
echo on|off                   дублировать в источник
mirror on|off                 зеркало в USB
syslog on|off                 логи ESP-IDF в USB
log 100 | log clear           журнал
wifi <ssid> <password>        подключиться к AP
ota                           обновление с GitHub
otacheck                      проверить версию на GitHub
auto 5000 1 AT                автокоманда каждые 5 с
monitor on|off                (telnet) показывать трафик
charset cp866|utf8            кодировка вывода терминала
passwd <новый>                сменить пароль (путь в вебе + telnet)
cmdmode url|mqtt|both         канал HEX-команд (адрес / MQTT / оба)
mqtt <uri> <topic> [user] [pass]  брокер MQTT
time                          текущее время (NTP)
ntp <server> [tz]             сервер NTP и часовой пояс
reboot
```

## HTTP API: отправка команды

`POST /api/send` (требуется cookie авторизации):

```json
{"data":"AT"}                                  → оба UART
{"target":1,"data":"AT"}                       → UART1
{"target":2,"format":"hex","data":"41540D"}    → UART2
{"target":"both","data":"AT"}                  → оба UART
```

Поля:

- `data` — отправляемые данные (обязательно);
- `format` — `"text"` (по умолчанию) или `"hex"`;
- `target` — `0` (только USB), `1` (UART1), `2` (UART2), `3` (оба UART);
  допускаются строки `"usb"`, `"uart1"`, `"uart2"`, `"both"`, `"all"`.

**Если `target` не указан или некорректен, команда уходит на оба UART.**
В ответе указывается цель: `{"ok":true,"msg":"отправлено 4 байта, цель оба UART"}`
(к `AT` автоматически добавляется `\r\n`).

## Каналы HEX-команд

Режим выбирается в веб-карточке «Каналы команд (HEX)» (`cmdmode` в CLI).
Цель по умолчанию — `1` (UART1), `2` (UART2) или `3` (оба).

**Адресная строка** (нужен тот же секретный путь `/<пароль>`):

```
http://10.10.100.235/sec?hex=41540D&target=3   -> OK bytes=3 target=3
http://10.10.100.235/sec?hex=41540D            -> цель по умолчанию из настроек
http://10.10.100.235/sec?log=50                -> последние 50 строк журнала
```

HEX пишется плотно, без пробелов и `%20`. Разделители (`,`, `;`, `:`) тоже
допустимы, но не нужны; нечётная цифра трактуется как `0x0N`. В вебе HEX можно
вводить с пробелами — при отправке они удаляются: URL, MQTT и `/api/send`
получают строку вида `41540D`.
В режиме «только MQTT» адресный канал отдаёт `403 URL channel disabled`.

**MQTT** (адрес `host`, `host:1883` или `mqtt://host:1883`; без порта
подставляется `1883`, базовый топик по умолчанию `pass-through-uart`):

| Направление | Топик | Payload |
|-------------|-------|---------|
| устройство ← команда | `<base>/rx`, `<base>/rx/1`, `<base>/rx/2`, `<base>/rx/3` | HEX: `41540D` |
| устройство ← код | `<base>/code` | HEX: `41540D`, цель из `<base>/target` |
| устройство ← цель | `<base>/target` | `0|1|2|3` или `usb|uart1|uart2|both|all` |
| устройство → результат | `<base>/result` | `OK bytes=3 target=2` |
| устройство → код | `<base>/tx/code` | `41540D` (плотный HEX команды, retained) |
| устройство → цель | `<base>/tx/target` | `0|1|2|3` (retained) |
| устройство → трафик | `<base>/traffic` | строка журнала |
| устройство → статус | `<base>/status` | `online` (retained) |

Подписка идёт на `<base>/rx/#` (покрывает `rx`, `rx/1`, `rx/2`, `rx/3`),
`<base>/code` и `<base>/target`. Отдельная подписка на `rx` не нужна: `rx/#`
совпадает и с родительским топиком, а две подписки доставляли бы команду
дважды.
Суффикс `/1`, `/2`, `/3` в `<base>/rx/...` задаёт цель для одной команды; отдельные
`<base>/target` + `<base>/code` задают цель один раз и затем шлют только код.
Текущая цель видна в статусе как `mqtt.target_effective`. Пустой пароль MQTT
в вебе означает «оставить прежний».

## Время (NTP)

В веб-карточке «Время (NTP)» задаются сервер (по умолчанию `pool.ntp.org`) и
часовой пояс в формате POSIX TZ:

```
MSK-3                          Москва / UTC+3
UTC0                           UTC
CET-1CEST,M3.5.0,M10.5.0/3     Центральная Европа с DST
```

То же можно задать командами `ntp <server> [tz]`; текущее время показывает
`time`. Статус синхронизации, сервер, пояс и смещение доступны в `/api/status`
в объекте `time`. В мониторе вверху есть часы, тикающие раз в секунду; строки
журнала после синхронизации получают метку `dd.mm HH:MM:SS` вместо uptime.

## OTA

Первый раз прошейте по USB (см. «Сборка и первоначальная прошивка по USB»).
Дальше прошивку можно обновить двумя способами:

- **локальным файлом** — в карточке OTA выберите `build/PassThroughUART.bin`
  и нажмите «Прошить из файла»; файл отправляется целиком на `/api/ota/file`
  и пишется прямо в свободный OTA-слот;
- **с GitHub** — адрес зашит в прошивку:
  `https://github.com/golnet1/uart_transparent_bridge/tree/main/build`
  (для загрузки используется raw-ссылка на `PassThroughUART.bin`).
  Кнопка «Обновить» или команда `ota` запускают скачивание оттуда.

Для обновления с локального компьютера нужен **только**
`build/PassThroughUART.bin` — это образ приложения (сейчас ~1,1 МБ). Другие
файлы из `build/` при OTA не используются: `bootloader/bootloader.bin`,
`partition_table/partition-table.bin` и `ota_data_initial.bin` записываются
только при первоначальной прошивке по USB. Не подменяйте их при обновлении —
достаточно выбрать `PassThroughUART.bin` в карточке OTA.

Версия берётся из `version.txt` в корне репозитория и сравнивается с `APP_VERSION`.
Проверка выполняется при старте (после появления STA) и раз в сутки, а также
кнопкой «Проверить обновления» / командой `otacheck`. Если найдена новая версия:

- с включённой галкой **«обновлять автоматически»** прошивка скачивается и ставится
  без подтверждения;
- без галки в карточке появляется надпись «Доступна версия …» и кнопка «Обновить».

После успешной установки ESP32 перезагружается в новый слот; старый слот остаётся
для отката.

## Резервная копия настроек

В той же карточке «Обновление прошивки (OTA)» есть две кнопки:

- **Сохранить настройки** — скачивает JSON вида
  `pass-through-uart-1.0.5-ГГГГММДД.json`;
- **Восстановить** — загружает такой JSON и применяет все настройки.

Обе кнопки находятся в одном ряду. Файл содержит скорости UART, мост,
автоскорость, Wi-Fi, MQTT, NTP, галку автообновления и
**хеш веб-пароля** (не открытый пароль, но файл всё равно следует хранить в
безопасном месте). Хеш восстанавливается вместе с настройками; сервер сразу
выставляет новую cookie, поэтому повторный ввод пароля не требуется.

То же через API (нужна cookie `PTUART`):

```
GET  /api/config/export   → JSON-файл с Content-Disposition: attachment
POST /api/config/import   → {"ok":true,"msg":"настройки восстановлены из файла"}
```

Совместимость: импорт принимает как полный файл с полем `config`, так и плоский
JSON с теми же полями, что и `/api/config`. Версия прошивки сейчас **1.0.5**.

## Замечания

- Журнал хранится в оперативной памяти и сбрасывается при перезагрузке.
- UART0 используется одновременно как USB-зеркало и как источник команд,
  поэтому системный консольный драйвер отключён (`CONFIG_ESP_CONSOLE_NONE`),
  а логи ESP-IDF перенаправлены в общую шину событий.
- На ESP32-WROVER не используйте GPIO16/17 для UART2 (там может быть PSRAM) —
  по умолчанию выбраны GPIO25/26.
